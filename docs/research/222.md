# Voice transcript replies (#222)

Recognized speech now leads the first answer or card as a collapsed microphone quote, replying to the original message. The answer shares that message. This applies R13, R18 and pilotq.md §§4 and 12; the owner text and display contract are in [Telegram feedback](../telegram-feedback.md).

## Failure and protection

Before the fix, `cargo test --locked voice_222` with the new regression cases on the original implementation failed both checks: drafts lacked the transcript prefix, and long transcript parts lacked expandable quotation formatting. Audio transcripts already existed in the journal; video speech was only temporary model input and needed persistence for failure/restart display.

After the fix, `cargo test --locked voice_` passed the two new regression tests and three existing voice integration checks. The retained protections cover answers, saved plans and choice cards with buttons, failure after recognition, verified stop, restart, unchanged recognition failures, captions excluded from the quote, literal speech escaping, UTF-16 splitting, rich/HTML/plain fallback, individual chunk receipts across reopening and no extra transcript message. Card edits retain the original quote; secondary notification destinations do not receive private speech (R10, §4).

The existing `telegram_voice_becomes_sender_text` test now checks actual outbound Bot API payloads for a voice note, an audio file with a caption and an audio document. Each sends one answer with the collapsed quote and original-message reply parameters. This is local adapter/process evidence, not Telegram visual qualification. Video speech persistence is checked at the journal boundary; its model input remains file source material rather than authorization.

The initial Cargo invocation was sandbox-blocked by the read-only default cache. Verification used a temporary writable Cargo cache and initialized the existing pinned specq submodule without changing its pin.
