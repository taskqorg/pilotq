# PilotQ cleanup (#373)

## Question

Remove completed experiments and records, retire unserved journal migrations, update CoreQ/runtime, and split the largest persistence and dispatch files without changing authority or recovery behavior. [Task #373](https://github.com/taskqorg/pilotq/issues/373) owns the acceptance and approved schema change.

## Findings

Current ASR limits remain in [#344's summary](344.md) and the [tester guide](../tester-guide.md#gigaam-multilingual-provisioning); speech fixtures and `voice.rs` remain. Retired-record links point to their original tasks, published release or immutable source sections. A local Markdown-link scan also found and repaired two incorrect relative adoption links in #199.
- **A3 — contract first (§9, R5/R18):** The accepted PM answer in #373 reports pds18 as the only serving host, running PilotQ 0.2.41 and journal schema 14. Mac's unserved schema-7 journal and Windows are not serving. No additional host access or installed changes were performed. Existing older databases require a compatible earlier build to migrate first; they are never reset.
- **A4 — reuse (R12, §9):** CoreQ is pinned to v0.19.2 (`b78ca64cac615500b57b4a04983e79333035dd65`) and agentq-runtime 0.4.1 to `33cef656ba86536e4e7f970ed5fc637b81622b06`. Installation prepares the executable bytes, then activates, before the existing service-unit steps. No `install_self` call remains.
- **A5 — unchanged boundaries (§§2,4,5, R13/R17):** Journal creation, admission, delivery, people, service state, requests and tasks have separate modules; tests remain together. - **A6 — current facts and consistent time (§6):** FRA installation instructions now identify retired history or target pds18. Optional Langfuse export assumes neither an existing installation nor approved capture. [Shared time rendering](../../src/time.rs) covers countdowns, ages and UTC exact times in footer/status, progress, drain blockers, loops and release observations. RFC 3339 source data remains machine data; display strings are never parsed back. The already locked Chrono dependency supplies date parsing/formatting without a new date implementation.

The retired-schema guard failed before the change because a populated unstamped database opened successfully; it now checks versions 0–12 are refused without schema or data changes.

Retired migration assertions for schemas 1/7/8/9/10 are removed with that support. Retained protection covers schema-13 native-session migration, pre-upgrade question receipts, policy refresh, newer/corrupt refusal, accepted-work preservation, grants, fencing and no replay. Conversation/release assertions change only their accepted time representation; task identity, pipeline facts, language, delivery and authority assertions remain.

Read-only review caught and corrected Russian direct-control countdown localization and lost source-specific audit anchors. The same loop-status boundary and shared time tests protect the corrected output. Development used affected Cargo filters and a temporary cleanup/link scan. The final result records the exact candidate SHA and canonical contract, locked Cargo and selftest outcomes. ## Options

- Keep completed artifacts and migrations: retains in-tree history, but leaves obsolete procedures and unsupported compatibility paths in current source.
- Remove them after the accepted host readback: keeps current source focused and preserves history in Git/tasks, but old unserved journals need an earlier compatible migrator.

## Verdict

The second option implements the approved cleanup. Publication remains subject to independent review and green merge-result CI; no live installation is included.

## Recommendation

Accept the cleanup only with the result's exact candidate checks and the normal merge queue. Keep all release and live-qualification boundaries in §9.
