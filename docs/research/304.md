Native setup registers no projects, so it starts no board-observer TaskQ reads. The fake HTTP listener writes only in-memory state. No real model, token or board is needed.

Other direct teardown callers were inspected: current-question/final-delivery checks own SQLite connections only; admission/readiness fixtures use registered fake boards and can have separate observer reads. The existing shared `cleanup` helper retries removal within fifteen seconds for those observers, but does not itself prove they have ended. Those different fixtures are unchanged; this repair does not claim to qualify their writer lifecycle.
