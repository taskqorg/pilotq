# Reserved A40 fixture host admission (#291)

The A40 harness prepares explicitly synthetic unserved host metadata before real TaskQ admission. Production validation, readiness and worker policy are unchanged (§5, §9, R16, R19).

## Question

How can the unique reserved A40 host pass TaskQ 4.6.58 host-name validation without enrolling a service or routing work to an ordinary host?

## Findings

### Failure before

The [#281 run4 reconciliation](https://github.com/taskqorg/pilotq/issues/281) records source `62d2be8dd7f60d23490975fb546fd9e71d758d1d`, TaskQ 4.6.58, exit 101 after 92.18 seconds and no OOM. Admission, discussion and plan passed; create/start failed, nine cases were not run and cleanup failed with `cannot reconcile create`. Both attempts of the stored add operation were rejected for the unknown reserved host before creation: `ticket.task=null`, no accepted add receipt, and zero matches in complete board status and independent operation-ID search. The original rejected operation arguments, journal, report and runner result remain in #281's private run4 evidence. Their exact operation ID is not reproduced here because it was not exposed in the public reconciliation; the PM must retain those originals. Manual reconciliation is not an automatic cleanup pass. The PM verified copied authentication absent and removed only the ephemeral board token; ordinary services and durable credentials were preserved.

No old-source retry or real board mutation was used to reproduce this already observed failure.

### Supported metadata

Inspection of [TaskQ v4.6.58](https://github.com/taskqorg/taskq/tree/v4.6.58), commit `dd695b8d1ad2fec03853ea4c6edff3d66faf7acb`, established:

- `src/main.rs`, `task_body`: `add --host` accepts names from trusted open issues through `service::host_name`, rejecting unknown names before creation.
- `src/service.rs`, `is_host` / `host_name`: the metadata uses label `taskq-host` and title `taskq host <name>`.
- `docs/design/host-service.md`, “Heartbeat lines, renames, retirement and freshness”: closing the metadata issue retires the host; only open metadata participates in host discovery.

The fixture creates this supported metadata shape with an exact unique reserved title and an explicit synthetic, unserved body containing `focus off`. It supplies no version, service identity, machine, child, session or ordinary worker claim. Missing service health remains unknown. This metadata permits name validation; it proves neither a running service nor worker eligibility. No TaskQ production validation changes.

### Change and retained protection

The private report saves host intent before POST and the returned issue number before any task add. A complete paginated listing over open and closed host issues reconciles an interrupted POST by exact title and body. Foreign bodies, duplicate matches and reuse of retired metadata refuse. An uncertain POST is never blindly repeated.

Task reconciliation retains the existing recorded exact add arguments and operation ID while metadata remains open. Known accepted receipts identify tasks without another add. Cleanup parks tasks, restores only the fixture's own pause and retires matching host metadata with closed-state readback only after reconciliation succeeds. Unresolved work retains its metadata and failed cleanup finding for the PM. Copied board credentials are removed even on cleanup panic, with an additional drop guard for unwinding outside normal finish; the existing copied-login guard remains. A hard kill still needs PM reconciliation.

The native/structured fixture binding, reserved host on add/retries, held/readback/start checks, no-worker rule, readiness findings and supported owner override, stranger protection, candidate identity and all fourteen A40 cases remain. The harness uses its existing synthetic-event forge mechanism only for fixture metadata. Production manager code, services, grants, focus, capacity, models and logins are unchanged (R9, R10, R13, R16, §5, §9).

### Verification

`python3 tests/support/automatic_host.py` passed, retaining native scope and identical reserved-host arguments across creation, retries and cleanup. `cargo test --locked --test telegram a40_ -- --nocapture` passed eight checks, with the live A40 check ignored. The new harness regression uses a fake forge to exercise paginated discovery, repeat preparation, retirement, interrupted creation, duplicate/foreign refusal and copied-token removal on cleanup failure and drop. It invokes the actual harness methods in a child with isolated PATH; no subscription, board credential or service is used.

Initial compilation was blocked by an uninitialized worktree `specq` submodule. Initializing its existing pinned revision resolved that setup failure. A pagination bug in the new fake forge was corrected before the focused pass. Candidate-gate results are recorded in the task result and PR.

This is component evidence after the fix, paired with the attributed run4 failure before it. It is not an executable before/after real-TaskQ admission run or full A40 qualification. #281 must run all fourteen cases and cleanup on the exact accepted merge with green required merge-result CI. No release, live installation or production cutover is qualified.

## Options

- Prepare explicitly synthetic reserved host metadata. Gain: uses current real TaskQ name validation without a service; cost: metadata needs durable reconciliation and retirement. Selected.
- Use an ordinary host label or enroll a reserved service. Gain: a discoverable host; cost: risks ordinary worker execution or violates the no-worker fixture protocol. Rejected by acceptance.
- Relax TaskQ validation. Gain: avoids metadata; cost: weakens production protections and exceeds scope. Rejected.

## Verdict

The missing supported host metadata explains the observed refusal. The harness now prepares and retires it while preserving admission protections. Full live-suite evidence remains open.

## Recommendation

Accept the exact merge only after required merge-result CI, then have #281's PM prepare a fresh private fixture and run the complete suite and cleanup. Never retry run4's old source or reuse its host identity.
