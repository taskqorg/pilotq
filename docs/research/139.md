## Findings with evidence

Inspected baseline: PilotQ `139a3c4a4035c52e13dd8612078c220699971ce6`.

- **Already present:** [AGENTS.md](../../AGENTS.md) binds workers to specq;
  [§12](../../pilotq.md#12-proposed-lifecycle-and-feedback-protocol) delegates
  presentation to [Telegram feedback](../telegram-feedback.md). Its #95 decision
  already requires compiled shared sources and instruction-change rebuilding.
  Core already says answer first, omit filler and repeated summaries, retain
  uncertainty and material conditions. #72/#82 already require short plans,
  paragraphs, flat lists, restrained emphasis and readable links. These are not
  missing shared rules. Adding another general brevity policy is unnecessary.
- **Confirmed integration gap:** [instructions.rs](../../src/instructions.rs)
  included Core, Agents, Indicators and Notifications, plus task preparation and
  intake sections. It did not include Documentation or Change communication.
  Task titles and bodies are persistent content, not merely chat replies. The
  old introductory sentence named preparation/admission only; it did not map
  communication profiles to all manager surfaces. The new preamble maps them
  explicitly and compiles both canonical profiles without copying shared rules.
  This proves missing instruction content, not that it caused every poor reply.
- **Confirmed renderer repetition:** [Journal::finish](../../src/journal.rs)
  replaced model text after saving a plan with “Draft saved locally. **Plan
  draft** · pilotq” and “Current draft; nothing filed on the board.” The model
  cannot shorten this generated introduction. The new receipt uses one line:
  “Draft saved locally. **Updated plan** · pilotq. Nothing filed on the board.”
  Full ticket goals, acceptance, scope and Launch/Cancel guidance remain intact.
  [TaskQ tool instructions](../../src/taskq.rs) already forbid repeating the
  rendered draft in final model prose. They remain unchanged.
- **Separate pins and responsibilities:** the PilotQ binary compiles the gitlink
  `a21e49e53c8234ba8922b2b325c3a489aad89eb2`. This worker attempt received
  `332b64ece748c95b21262f82c3ded1d5b38e4b5f` through TaskQ. Updating the worker's
  rules does not update an installed manager binary. Both profiles used by this
  change already exist in PilotQ's pin; no shared-rule change or pin bump is
  needed. PilotQ does not launch or instruct workers itself.
- **TaskQ comparison:** [runtime.rs at v4.6.41](https://github.com/taskqorg/taskq/blob/v4.6.41/src/runtime.rs)
  defines `SPECQ_CORE` (including Core, Documentation and Changes),
  `shared_revision`, `rules` and `compact_context`. It fetches a verified shared
  snapshot and injects contract/core bodies at starts and continuations, with
  revision and precedence. PilotQ embeds selected sources at build time and
  passes them through `developerInstructions`, without repository access from
  its restricted manager. TaskQ's stronger delivery coverage does not prove its
  generated prose always follows the rules; this report makes no such claim.
- **Recovery already exists:** [fingerprint](../../src/instructions.rs) hashes
  policy, tool instructions and tool catalogues. [Journal::open and rebuild](../../src/journal.rs)
  mark existing native threads for refresh when that hash changes, supply
  recorded requests, replies and receipts, and never replay completed effects.
  [manager.rs](../../src/manager.rs) sends developer instructions on both
  `thread/start` and `thread/resume`, and on a new start after a missing native
  thread. The existing `instruction_change_rebuilds_once` check protects the
  once-only refresh and retained transcript. No new recovery mechanism is added.
- **Delivery is a different boundary:** [telegram.rs](../../src/telegram.rs)
  already turns paragraph soft breaks into rich Markdown hard breaks, escapes
  source HTML and converts the supported subset for HTML fallback. Plain
  fallback sends literal source, including Markdown marks and link URLs, without
  parse mode. Plain therefore preserves content and line separation but cannot
  promise rendered bold or labeled clickable links. Worker questions use the
  deterministic #95/#97 relay, not model rewriting; their source content and
  numbered options remain covered by `u95_scripted_reply_task_question_status`.
- **Duplicate work avoided:** open #137 concerns installed command availability
  and live command execution after #126. This change does not alter the executor,
  allowlist, grants, tool catalogue or command setup. Only the representation of
  an observed command result is in #139's scope.

No inspected evidence establishes a new formatting defect in rich or HTML
transport, or establishes the wording of the original Telegram examples. Do not
substitute adapter fixtures for observations from the live conversation.

## Options and recommendation

- Repeat a brevity sentence only. Advantage: tiny change. Disadvantage: leaves
  the missing persistent-content profiles and deterministic repetition intact.
- **Apply existing profiles at the missing boundary and shorten the renderer
  receipt (implemented).** Advantage: fixes demonstrated gaps without new
  infrastructure or changing source questions. Disadvantage: live model behavior
  still needs observation; instruction delivery is not compliance proof.
- Add a model rewrite or hard length limit. Advantage: can shorten output.
  Disadvantage: risks losing source questions, material conditions and uncertainty,
  adds latency and conflicts with the unchanged relay contract. Not selected.
