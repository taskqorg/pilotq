# Short-video frame decoding (#341)

PilotQ §1 requires real video frames; §12 and Telegram feedback retain bounded media handling. This repair changes no admission, capacity, audio-recognition or release authority (R13, R19, §9).

## Evidence and diagnosis

The PM supplied private request-412 audit and the synthetic sender original in ignored `target`. The audit records video intake and `the video could not be decoded`. The sender original is 53,977 bytes, H264/yuv420p, 320×180, 10 fps, three seconds, without audio. Telegram-received byte identity is unknown. Private audit bodies and sender identities are not included here.

On this host, configured `/usr/bin/ffmpeg` is 8.0.1-3ubuntu2. Running the existing decoder arguments on the original exits 234: `Non full-range YUV is non-standard` and `ff_frame_thread_encoder_init failed`. Selecting `-pix_fmt yuvj420p` alone succeeds but produces no JPEG: default FPS rounding discards the short interval. Adding `fps=1/15:round=up` produces one JPEG. This isolates an encoder pixel-format compatibility failure and a separate short-sampling failure; the same executable succeeds without changing resource limits. It does not establish a host capacity failure.

The service user bus is unavailable in the worker session, so live unit limits/environment parity could not be inspected. Worker process address-space and CPU limits are unlimited; exact live-service reproduction remains a PM qualification gap. No live journal, service or configuration was changed.

## Repair and regression

The shared `voice::frames` decoder explicitly chooses JPEG full-range YUV and rounds partial sampling intervals up. Container signature admission, file-only protocols, original deadline, process supervision, private temporary directory cleanup, 1280-pixel width limit and four-frame cap remain unchanged. Audio handling is unchanged.

The existing ignored real-ffmpeg component check now also generates a synthetic three-second H264/yuv420p 320×180 clip without audio. It failed before the repair with `the video could not be decoded` and passed afterward. It retains the 62-second four-frame case, corrupt MP4 and prohibited playlist checks, and verifies absent audio returns a decode error rather than fabricated speech. Run explicitly where ffmpeg/libx264 is available:

```sh
cargo test --locked --bin pilotq video_frames -- --ignored
```

The repaired exact command also decodes the staged sender original to one JPEG. These are decoder observations, not visual/model or Telegram acceptance.
