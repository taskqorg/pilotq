# Document parsing deadline and cancellation (#195)

Document parsing now shares the media preparation deadline and observes the active journal fence. A stuck parser runs in an isolated child; timeout or cancellation terminates its process group and reaps the child before returning.

## Question

Can document parsing retain the accepted content and exact failure reasons while releasing a stuck parser on the existing media deadline or `/stop`?

## Findings

[Task #195](https://github.com/taskqorg/pilotq/issues/195) retains the owner’s [#186 A2](https://github.com/taskqorg/pilotq/issues/186) requirement: “the reply describes the real content or names the exact reason it cannot.”

This implements §§1 and 12 and R5/R13 through the existing media and request boundaries. The supporting specification is [Telegram feedback](../telegram-feedback.md). PDF text, UTF-8 text, ZIP listing without extraction, the existing content caps and exact unsupported/damaged/scanned reasons remain intact.

### Before and after evidence

Before the fix, a controlled child slept for one second before returning a valid result. With a 50 ms media deadline, `cargo test --locked --bin pilotq stuck_document_deadline -- --nocapture` failed: the unbounded wait returned `Ok("late")` after 1.01 seconds instead of a timeout. This safely reproduced the missing supervision without a hostile PDF.

After the fix, `cargo test --locked --bin pilotq files::` passes four checks:

- A controlled 30-second parser is terminated at a 300 ms deadline; its PID no longer exists when the call returns.
- An admitted Telegram `/stop` advances the actual journal fence during a controlled stuck parse. The call returns cancellation within two seconds and the parser PID no longer exists.
- JSON transport preserves readable content and exact failure reasons; invalid output is rejected. Expired deadlines and inactive fences refuse dispatch.
- Existing PDF/text/ZIP and damaged/unsupported checks pass, with an added scanned-PDF check preserving the exact no-extractable-text reason.

The offline selftest additionally checks the real binary’s child entrypoint, private input file and UTF-8 result transport. Input is unlinked before dispatch and closes with the parent/child file descriptors; document bodies remain outside the journal. Timeout records `file_read` rather than starting a model with an exhausted budget. Review of the first candidate found that the generic failure projection hid the parsing reason from the reply. The corrected journal projection now retains the localized timeout reason in the durable reply and Telegram outbox. Cancellation retains `/stop`’s existing fenced outcome.

The requeue regression, `cargo test --locked --bin pilotq document_timeout_reply_195 -- --nocapture`, failed before the projection fix: the stored reply was “The request failed; try again or check /status.” instead of “Document parsing timed out.” After the fix it passes for English and Russian, checking the failed state, exact internal reason, localized durable reply, rich delivery outbox and reply persistence after journal reopen. Existing stop fencing remains authoritative and suppresses late replies. This corrects the first candidate’s overstatement about user-visible exact reasons (A2, §1).

### Limits

These are local process, parser and journal checks. They do not qualify live Telegram delivery or authorize deployment (§9). The controlled child proves supervision of a stuck parser; it does not claim that every possible malicious PDF has been enumerated. Final candidate checks and CI status belong to the PR and TaskQ result.

## Options

- Keep parsing in the manager thread. Pro: no process transport. Con: a stuck parser cannot observe the deadline or journal fence, as the reproducer demonstrates.
- Isolate parsing in a child with the existing bounded runner. Pro: timeout and stop release parser resources while retaining the existing formats. Con: each document needs a process and private input transport.

## Verdict

Confirmed locally: the isolated parser preserves the accepted formats and reasons, and the controlled stuck-parser checks prove timeout and journal-stop cleanup. The corrected candidate suite passed 199 tests with 10 existing live/media cases ignored; offline selftest passed through the real child entrypoint. Merge-result CI and live Telegram remain unqualified here.

## Recommendation

Accept the isolated parser after required merge-result CI; retain the existing §9 release and live qualification boundaries.
