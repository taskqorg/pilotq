# Superseded unanswered question controls (#324)

Task [#324](https://github.com/taskqorg/pilotq/issues/324), “Remove buttons from superseded unanswered Telegram questions,” requires retiring obsolete controls while preserving current answers, routes and stale/repeated callback safety. This implements the existing source-card requirement in §2 and durable ordered delivery in §4; it changes no answer authority, schema or release permission (§5, §9, R19).

This worker did not inspect private live messages or install a build. The installed observation remains attributed to the task; the following reproduction uses invented inputs and fake Telegram/TaskQ adapters, not a fresh installed-version qualification.

It moves the fake board through ready/doing/ask, receives the replacement question, and requires an empty keyboard on a factual edit of the original unanswered message. TaskQ lifecycle validity is separately protected by the unchanged A40 transition-readback check; the fake board is not evidence of TaskQ fold semantics.

Source diagnosis preceded implementation: `Journal::observe` queued each new question but no edit for an older unanswered question. `answer_question` created edits only for trusted accepted answers. Delivery already resolved accepted-answer edits by project, task, revision and route; callback dispatch separately fenced stale revisions. Thus the owning defect was missing journal presentation work, not answer authorization or TaskQ transitions.

## Change and retained protections

A new trusted ask commits one `question_superseded` edit per older unanswered revision in the same transaction as the replacement question. Selection retains request, project, task, chat and topic boundaries. It excludes accepted-answer receipts and existing retirements. The edit retains original question text and adds a localized supersession statement without attributing an answer. The delivery resolver finds the original question's message in its saved route; rich, HTML and plain edits remove the keyboard.

Retirement is ordered before replacement. An original question still awaiting delivery obtains its message receipt before its retirement edit resolves; restart retains both obligations. Retirement never becomes an accepted-answer receipt, so a later trusted answer can still restore its factual author and revision through the existing answer path. No result-image source or transport changes.
