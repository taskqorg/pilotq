# Task result images and owner choices

## Question

How can PilotQ deliver accepted board-only CSGO review images and record the owner’s
variant selection in Telegram without a checkout or a second task/answer mechanism?

[Task #273](https://github.com/taskqorg/pilotq/issues/273) requests actual CSGO review
images and variant choices inside PilotQ CSLP. The owning contract §5 now covers bounded
board-bound artifact retrieval, inline images, current access and existing TaskQ choices
(R4, R5, R8, R10, R13, R16, R17). The task links the original owner requirement.

## Findings

Before the change, `cargo test --locked --bin pilotq result_images_273_entry_point`
failed because the scoped image-delivery capability did not exist. The same check passed
after implementation. The first development invocation also exposed an uninitialized
`specq` submodule; initializing the pinned submodule restored the repository's build input
without changing its gitlink.

TaskQ remains the sole source of task state, trusted attachment references and questions.
The narrow artifact exception downloads bytes from the registered project's GitLab uploads
API, with protected `issue_read` key injection and no redirects. Both upload-ID references
and Markdown upload paths resolve to the registered project's API. A web-route 404 never
proves the accepted result is absent. The mechanism follows the documented
[GitLab upload API](https://docs.gitlab.com/api/project_markdown_uploads/#download-an-uploaded-file-by-id).

Only JPEG/PNG members are inflated from ZIPs, in memory, with size, count, path, type and
checksum bounds. Code and archive scripts are never extracted or executed. Photo bytes
and immutable destinations enter the existing journal outbox; individual Bot API receipts
record delivery independently of work. Original task question cards retain revision and
operation fences. Visual option answers also carry the stable Telegram actor in TaskQ.

The contract lint initially rejected an overlong added line. Reflowing that paragraph
and existing architecture lines preserved every clause within the 300-line/400-character
limits; `scripts/check-contract.sh` then passed.

## Verification and open qualification

The focused `result_images_273` checks cover protected HTTP dispatch, project-bound upload
references, safe ZIP image reading, actual multipart Telegram photo transport, durable
receipts and access/rebinding boundaries. Existing answer tests retain stale, unauthorized,
repeated and same-operation recovery protections. The candidate gate and PR identity are
reported in the task result rather than inferred from implementation.

The [A273 checklist](../acceptance.md#a273--board-only-task-result-images-and-visual-choices)
reserves real images and a disposable choice round trip for the PM after merged release.
No live service installation, real artistic choice, paid provider or production cutover
was performed by the worker (§9, R19).

## Options

- Use board-bound upload bytes and the existing outbox/question boundaries, as implemented.
  Advantage: inline images and exact option/actor receipts work without a checkout.
  Cost: authenticated artifact retrieval and media errors need explicit qualification.
- Keep link/ZIP-only reports. Advantage: no additional media handling. Disadvantage:
  this fails the owner's inline-image requirement and is not an accepted alternative.

## Verdict

Local implementation checks pass: 284 tests passed, 11 live/opt-in cases were ignored,
and the contract check and offline selftest passed. Real CSLP image appearance and the
disposable answer round trip remain unqualified until the post-release PM check.
The candidate is in [PR #289](https://github.com/taskqorg/pilotq/pull/289); publication
still requires green merge-result CI. This report proves no live installation or cutover.

## Recommendation

Merge through the qualified merge queue, then release and execute the existing A273 PM checklist.

Keep the scoped upload/outbox implementation and the original TaskQ answer protocol.
Record the PM's real-image and disposable-choice evidence before claiming live qualification.
