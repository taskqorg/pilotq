# Clear task explanations across delivery paths

## Question and owner decision

Task updates must explain what happened, why it matters and what a person chooses, while preserving source evidence and TaskQ authority (R8, R13, §§2, 5).

Original owner request, linked in #385:

> «Нужно разработать единый формат, единый стандарт, таких удобных ответов»
>
> «Если есть вопрос, он задает в понятной форме вопрос и нормально объясняет варианты, и что он рекомендует».

The initial investigation found that arbitrary localized explanations require a model or upstream localized source. The accepted answer to question revision `6670422629` settled this, verbatim:

> Я думаю, давай сделаем так, что когда включен режим PM, то он просто объясняет карточку и вс<unk>. А когда режим PM отключен, то карточка приходит просто вот в том виде без использования моделей.

The implementation uses the existing `/review on` PM review turn to explain event cards. With review off, cards keep source prose and use no model. This supersedes the initial proposal for an upstream explanation producer; no upstream task or second model mechanism is needed.

## Findings and implementation

The contract changed first, followed by conversation-flow and supporting specifications. The manager and resumed sessions load those specifications through compiled instructions. Explanations lead with ordinary meaning, preserve original numbers and complete pros/cons, and state the recommendation and evidenced reason. Missing reasons and other facts remain unconfirmed. Immutable source remains in question receipts, board observations and audit; explanation alone authorizes nothing.

Before: PM review changes contained task state transitions, but not the complete source question, and questions/closures did not independently wake a review. After: these events wake the existing review, with full typed source question/options, title/link, revision and available verdict context. Review remains one per authorized person, coalesces pending work and stops under its existing grant/revocation boundaries. PM-off event cards create no model turn. The source question renderer localizes owned labels, retains literal choice contents and IDs, and uses the shared action-required icon. Source recommendations remain marked once; a separately unverified reason is identified as such.

Before: subscription `scan` called `close_task` whenever a task disappeared from the open snapshot, including when closed-result lookup failed. The affected start-gap test failed with `missing closed evidence must keep the subscription`. After: closure requires matching stable same-task closed issue/inbox state and URL; open, foreign, missing, changing and partial evidence cannot terminate a subscription. Accepted closing findings are a separate claim: absent findings remain unconfirmed. Verified full titles and URLs survive open-board disappearance in the existing audit store. Titles no longer lose essential words after an eight-word cutoff. Model-free state labels use the shared semantic icons and identify unconfirmed waiting actors rather than guessing them. Closed cards use the observation icon: closure alone never supplies a success badge for an unknown outcome. A second regression reproduced stale title overwrite; the older-revision fence now covers identity writes as well as state, and the affected check passes. Failed-test fixture directories use unique identities so a retained diagnostic database cannot alter a rerun.

The installed TaskQ closed snapshot for taskq#2451 exposes canonical publication/close history rather than `conversation.verdict`. Readback now supports that representation only when its current revision and exact IDs, kinds, authors and literal bodies match trusted unedited issue comments and the stable inbox. Existing resolved-verdict guards remain; missing or inconsistent history is not accepted. Ordinary closed task status can return that qualified verdict and its limitations rather than a bare `Repeats:` reference.
