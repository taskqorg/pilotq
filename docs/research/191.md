# Owner requirement audit (#191)

## Question

Which owner requirements were narrowed or lost between their original tasks, PilotQ’s specifications,
manager instructions, implementation and tests?

The [complete audit](owner-requirements-audit.md) covers every one of the 827 #177 inventory entries,
twenty current marked owner notes and all seventeen original `ponytail:` comments. It quotes source
task text and accepted decisions, gives specification/code/test `file:line` evidence and records
`met`, `narrowed` or `missing` with a disposition. The baseline is
`76994fbe28556794a53d4e931845b8b41f51ca03`, including #189 and #190.

## Findings

- **Fixed — formatting narrowed by an extension list.** [#82’s owner review](https://github.com/taskqorg/pilotq/issues/82#issuecomment-6480258198)
  requires repository paths to render as code. `tidy` supported only fifteen extensions and ASCII
  names. The existing path regression failed on `ui/App.vue` before the fix, then passed with
  unfamiliar extensions, Unicode names, line references and root filenames through Markdown and HTML.
  The link, code, URL, abbreviation and version protections remain.
- **Fixed — #190’s runtime authority contradicted by loaded instructions.** The root already grants
  full service-user access, but the linked discussion policy still restricted direct work to small
  reads/writes and a short-action budget. The policy regression failed before correction and passed
  afterward. [#190’s original owner text](https://github.com/taskqorg/pilotq/issues/190#issuecomment-6539418343)
  remains the decision source; this audit introduces no new authority. TaskQ-first task work,
  immutable launches, answer authority, typed-tool checks and interrupted-turn no replay remain.
- **Fixed — stale specification wording.** Feedback still limited rich delivery to “final replies”,
  despite §4/#189’s shared delivery path. Feedback, adoption notes, current acceptance cases and the
  installed-command guide now agree with #189/#190. Historical test results stay historical.
- **Missing — document parsing deadline/cancellation.** Synchronous PDF parsing has data caps but
  no enforceable execution-time or cancellation bound. The misleading simplification comment was
  removed. [#195](https://github.com/taskqorg/pilotq/issues/195) retains the existing formats and
  exact-reason requirement while requiring a safe stuck-parser reproduction and bounded cleanup.
- **Missing — scoped Telegram self-service.** Profile storage and operator controls exist, but
  Telegram lacks a scoped own-profile/access inspection and correction path. Native shell authority
  does not prove ordinary-user self-service. [#196](https://github.com/taskqorg/pilotq/issues/196)
  retains privacy, separate grants and restart/reset protection.
- **Missing — input edit and route lifecycle projections.** Ingress drops edited-message and
  migration events. Forbidden-send handling does not establish revision handling or route incidents.
  [#197](https://github.com/taskqorg/pilotq/issues/197) quotes the original clauses and requires
  durable outcomes without rerouting, repeated effects or model calls for service messages.
- **Missing — live and adoption proof.** [#198](https://github.com/taskqorg/pilotq/issues/198)
  collects PM-only scenario qualification after a merged release. Historical evidence is retained
  but does not qualify this artifact. [#199](https://github.com/taskqorg/pilotq/issues/199) covers
  the unresolved adoption/restore/storage/native-identity/agentq evidence and decisions. Proposed
  thresholds, agentq enablement and production cutover remain unapproved (R19; §§7, 9–11).

Every missing row links a read-back held follow-up; none was started. A3 explicitly permits this
outcome. The audit distinguishes specification retention, deterministic protection, actual
implementation and live evidence; a relocation map or a passing fake is not proof of all four.

## Options

1. **Keep the scoped fixes and admit the held follow-ups after PM readback.**
   Plus: repairs demonstrated narrowing while preserving source intent and qualification limits.
   Minus: document cancellation, Telegram self-service, lifecycle projections and adoption/live
   evidence remain open until their owning work completes.
2. **Accept the prior specifications without the fixes.**
   Plus: avoids changing the tested candidate.
   Minus: retains conflicting loaded instructions and the demonstrated path-formatting failure;
   this does not satisfy #191.

## Verdict

**Confirmed:** owner requirements were narrowed in the formatting and loaded-policy paths. Both
regressions were reproduced before their fixes and passed afterward. The audit is complete as an
inventory and evidence/disposition review; the linked missing behaviors and platform checks are
not represented as implemented or qualified.

## Recommendation

Accept the scoped fixes after the candidate gate and merge-result CI. The PM should read back and
triage held #195–#199; no release, deployment, production cutover or proposed operating threshold
is authorized by this report.
