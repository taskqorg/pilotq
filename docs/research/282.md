# A40 native TaskQ isolation (#282)

The fix binds native and structured A40 TaskQ calls to disposable fixture state. It does not qualify a release or live service (§9, R19).

## Failure before

The [task acceptance](https://github.com/taskqorg/pilotq/issues/282) names source `250cae1dd02f707b7686679758964ed8f6b4b6cd`. Its manager clears the environment, preserving HOME and PATH but dropping fixture TaskQ overrides. The harness configured only the structured recorder, leaving native resolution outside it.

A harmless child probe extracted that exact source's recorder and used the production environment allowlist. Against expected fixture `install` and `root` paths, a fake executable observed `TASKQ_INSTALL=null`, `TASKQ_ROOT=null` and the ordinary HOME. Native `taskq` lookup returned 127 in this worker sandbox. This establishes missing fixture binding; it does not claim an ordinary installation was executed. A separate fake-control check failed because a foreign installation reached dispatch with exit 0. No ordinary pause/resume or board mutation was used.

## Change and retained protection

The test recorder binds installation, root and working directory. A native PATH alias and fixture HOME alias resolve to that same recorder. Explicit foreign installation/root overrides and foreign project directories refuse before receipts or dispatch. The live runner requires sibling install/root directories under a caller-owned, private temporary `pilotq-e2e-*` directory, with only that root in the fixture installation registry. Its harmless preflight records the native scope before model startup.

Production manager code, environment clearing, credential scrubbing, subscription-only authentication and full-agent authority are unchanged (R9, R16, §3). Existing host fencing, operation reconciliation, all fourteen A40 assertions and cleanup remain. This harness boundary does not isolate an authorized full agent deliberately selecting an unrelated absolute binary (§5).
