# AgentQ manager runtime adoption

## Question

Can PilotQ use the shared AgentQ runtime while retaining the manager capabilities accepted in
[#265](https://github.com/taskqorg/pilotq/issues/265), durable delivery and rollback?
The owner-approved implementation and amended Windows qualification scope are recorded in
[#294](https://github.com/taskqorg/pilotq/issues/294).

## Findings

- **Contract first:** amended R9 and §§3/6/7 before implementation. Runtime execution belongs to
  AgentQ; CoreQ retains installation, process primitives and telemetry storage. Owner/shell authority,
  subscription-only access, model/effort/account selection and TaskQ admission are unchanged.
  Preference correction/forgetting detail remains binding in `runtime-contract.md` §6.
- **Immutable dependency:** `agentq-runtime` 0.1.0 uses remote revision
  `513193c8a96f3de1c71a86291a679230817ce0b2`, the published source pin supplied by AgentQ's
  [extraction](https://github.com/taskqorg/agentq/pull/183). `Cargo.lock` adds only that package
  and the consumer dependency; CoreQ stays v0.18.0.
- **Consumer inventory:** `manager.rs` uses AgentQ AppServer/AppSession for Codex turns, model
  catalogue and quota reads; `claude.rs` uses AgentQ Turn and session identities; `main.rs` and
  `host.rs` use its runtime selection/account checks; `slots.rs` uses its UUID utility.
  The only remaining `coreq::agent` calls are compatibility assertions in the portable tests.
- **Preserved boundaries:** the existing dynamic tool dispatch, private draft callbacks, native
  grants, route overrides, journal reconstruction, delivery outbox and TaskQ host-slot reservation,
  reconciliation and release remain in their existing consumer paths. No new scheduler or MCP
  framework is introduced. The existing Claude Unix relay stays in place.
- **Optional optimization:** configuration accepts `off` (default), `inherit` and `on`. AgentQ
  prepares a child launch without editing global configuration or installing an optimizer. Effective
  state/reason reaches request audit and the existing `runs.agentq` column; unknown stays unknown.
  `AGENTQ_LAUNCHER=pilotq` prevents duplicate optimizer accounting. An attached optimizer's privacy
  and host-disable controls prevail. This is not the dynamic-tool compression qualification (§11).
  Claude's existing `--setting-sources project` excludes user hooks; its child therefore forces
  compression off, preserves requested intent and records `settings_excluded` for `inherit`/`on`.
  A read-only review caught the initial false `on` observation; the portable regression now protects
  the selected settings boundary and the default-home mismatch without importing global settings.
- **Portable evidence:** `cargo test --locked --lib 294` passes three tests on Windows, including
  real child I/O against invented Codex app-server and Claude CLI events. They cover catalogue and
  quota reads without inference, exact resumed IDs, unknown-turn replay refusal, scoped recovery,
  one idempotent usage observation with route attribution, optional optimization and protected
  child environment. No real provider executable, login or Claude slot is used.
- **Failure before/pass after:** the first Windows fake-client test failed because host policy
  refuses `.ps1` files. The same test passes with an inline PowerShell command; execution policy
  is unchanged. Contract lint first caught 301 lines and one 401-character line; after preserving
  the existing preference detail in its linked owner page, lint passes at 300 lines/399 characters.
  The first candidate run also exposed an incorrect fake-client assertion that process exit must
  be zero: AgentQ intentionally terminates a lingering child after its native terminal event. The
  check retains confirmed termination plus exact native result/session assertions, rather than
  treating process exit alone as provider success.
- **Windows limit:** baseline `cargo test --locked 265` on `f86106a8` failed on Unix-only
  service/relay code and an uninitialized pinned specq checkout. The checkout is initialized; the
  service remains Linux-only. Full service tests and selftest cannot be claimed from portable tests.
  The candidate's canonical gate outcomes belong to the exact-SHA TaskQ result and PR CI.
- **Review correction:** the first candidate reverted main's package version to 0.2.38 and
  removed unrelated #316 image protections. A readback check failed for both Cargo versions,
  contract §5 and the image paths. Restored 0.2.39 in both Cargo files and restored §5,
  `src/keys.rs`, `src/result_images.rs`, `docs/telegram-feedback.md` and `docs/research/316.md`
  verbatim from main `39472f9`. The same readback now passes. This retains automatic non-image
  handling, localized ambiguous-key refusals and the existing #316 regression test (R18, §5/9).
  No assertion or accepted rule was changed; native image execution remains Linux CI-owned.

## Options

1. **Use the pinned AgentQ library.** Preserves the established transport APIs and subscription
   paths with a small consumer change. Requires separate native and release qualification.
2. **Keep CoreQ agent coupling.** Avoids the consumer change, but does not deliver the approved
   dependency direction in [the architecture](https://github.com/taskqorg/assetq/blob/main/docs/architecture.md).

## Verdict

Implemented with deterministic portable evidence. Native provider, complete Linux service and
exact-merge release qualification are separate claims; runtime adoption grants no production cutover (R19).

## Recommendation

Review the candidate through merge-result CI; retain the installed baseline until PM qualification and release gates pass.

## PM qualification and rollback

- Live pds18 Codex and Mac Claude: **Not tested on win worker (Claude limit 0; deferred to PM host run).**
  Claude remains disabled on every host. This report authorizes no real Claude launch, slot restore,
  new login, host-key bypass, model/account/capacity change or worker deployment.
- [#281](https://github.com/taskqorg/pilotq/issues/281) qualified all 14 A40 cases and independent
  cleanup on `f86106a8fb9a5f906be67b6be95e11649fbd58c5`. That source is the published/installed
  0.2.38 baseline. Its pass does not qualify this changed candidate. No fixture or active run is touched.
  Before the next release the PM coordinates one fresh full A40 plus independent cleanup on the
  exact accepted merge, using the established reserved fixture and bounded runner (§9).
- The PM owns bounded pds18 Codex proof through existing access and subsequent installed/live
  acceptance. Retain source/binary/runtime identities, exact native IDs across two turns and restart,
  tool/draft/model observations, one usage observation per turn and real TaskQ slot receipts.
- Schema remains 13 and session homes/identities are unchanged: Codex native thread IDs and
  `claude:<id>` journal values. The previous build ignores the new optional config key and audit
  kind. Portable compatibility checks recover an unfinished CoreQ checkpoint through AgentQ and
  back without replay, and reject another account scope. Existing service tests retain journal
  migration, recovery, delivery and slot guards; the added journal test checks audit persistence/fencing.
- Roll back only through the existing owner drain and previous immutable build. Preserve journal,
  sessions, pending delivery, uncertain effects and slot reconciliation; never replay a completed effect.
  This source/checkpoint evidence is not a live restore or service activation proof.
