# Automatic Russian/English speech (#344)

PilotQ uses stock GigaAM-Multilingual large int8 through the static sherpa-onnx-offline NeMo CTC path. [Contract §1](../../pilotq.md#1-scope-and-input-boundaries) owns the supported input and language requirements; [provisioning](../tester-guide.md#gigaam-multilingual-provisioning) pins current assets and checks.

## Findings and limits

The accepted route supports Russian and English without a language selector. Hebrew is not required. Output is lowercase without punctuation, with some English transliterated into Cyrillic; supported text languages are ru/en/kk/ky/uz.

Natural mixed human speech remains unqualified. Separate-clip and synthetic-join omissions are accepted route limits. Same-audio Russian comparisons retained 7/26/81 words; the 35-second sample was macOS synthetic speech and does not prove long human parity. Source checks and fake-engine tests do not qualify real recognition or live Telegram acceptance (R19, §9).

[Reply-language coverage](344-language-inventory.md) retains the Russian/English output boundary evidence. The completed engine experiments, host procedures and rejected candidates remain in [task #344](https://github.com/taskqorg/pilotq/issues/344) and Git history. They are not runtime or release prerequisites.
