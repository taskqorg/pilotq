# CoreQ observations in PilotQ (#374)

## Question

Implement [task #374](https://github.com/taskqorg/pilotq/issues/374): write PilotQ operations through
the shared CoreQ observation contract, obtain agent records from agentq-runtime, and retain the
old PilotQ path until a later parity task. The implementation follows R13, R16, R17 and §§8–9.

## Findings

- **A1:** `pilotq.md` §8 states the observation contract before implementation. The operation
  catalogue, installation path, audit joins and compatibility boundary live in the linked
  [runtime detail](../runtime-contract.md#telemetry-observations). CoreQ is v0.21.0 and
  agentq-runtime is pinned to `c80675a557417532393e143ca2783c0f4c83b8d9`.
- **A2:** CLI commands, terminal requests, manager capabilities, installed TaskQ calls, Telegram
  delivery and service passes write metadata to the existing CoreQ `telemetry.sqlite` store.
  Request text and tool output remain in the journal. Audit exposes request/trace IDs and
  `telemetry_links`; the relationship is resolved at read time. Missing values and unclassified
  unsuccessful tool results stay unknown with reasons. No second collector or exporter is added.
- **A3:** `Run::record` supplies `agent.turn` and `agent.call`. PilotQ neither parses model calls
  for telemetry nor synthesizes provider tokens, process usage or missing runtime identities.
  It checks the runtime's append result and attempts recording on terminal and interrupted paths
  after a launch handle is available. A runtime that cannot produce a report stays unavailable.
- **A4:** The journal, `pilotq.request` events and `pilot report` remain active. The old event and
  new terminal request observation append together. No store or report deletion is included;
  no same-window production parity is claimed.

## Verification

The first candidate, `b04914e`, had a review finding on A2. The fix commit records each failure before and its pass after:

| Finding | Rule | Before | After |
|---|---|---|---|
| `doctor` created the store | §9 | `doctor_missing_configuration_is_not_healthy` failed at `tests/update.rs:276` (left 5, right 0) | Passes unchanged; `doctor` installs no collector |
| An empty store read as zero failures | R17 | `pilot_report_prints_gate_counts_and_tool_window` failed at `tests/update.rs:184` | Passes unchanged; `pilot` never creates the store |
| Failed commands had no terminal record | A2 | `pilotq bogus` and `pilotq users grant notanid chat` left only start rows | `command_exits_374_leave_terminal_observations` passes |
| A failed link write blocked the request | §8 | The request stayed `running` | `telemetry_link_failure_374_never_blocks_the_request` passes |
| `/restart` lost buffered observations | A2 | `std::process::exit(75)` at `src/builtins.rs:112` | `coreq::telemetry::capture::exit(75)`, the same exit as a scheduled update |

Both new tests were run with their fix removed, and both failed. The link test also proves that a trace was current, because its healthy pass must write one link before the broken pass runs. The `/restart` change has no dedicated test: only an installed service reaches that path.

Linux candidate gate on `b194939`, from an LF checkout in WSL:

- `scripts/check-contract.sh`: passes at 300 lines, with the existing headroom warnings.
- `cargo test --locked --no-fail-fast`: lib 1 passed; binary 248 passed, 5 ignored; `telegram` 78 passed, 10 ignored; `update` 12 passed. This includes `u23_audit_through_service_and_cli`, which the earlier macOS sandbox blocked.
- `cargo run --locked -- selftest`: passes.

Windows portable check: `cargo test --locked --lib` passes 1 test. This does not qualify a managed Windows host. A Windows checkout with `core.autocrlf=true` cannot run the binary tests, because `src/instructions.rs` expects LF in its included documents. Linux runs therefore use an LF checkout.

Merge-result CI, live installation and same-window parity are not covered by these checks (R19).

## Options

- Keep `doctor` and `selftest` out of telemetry: preserves their §9 no-write boundary, but leaves those two commands without an observation.
- Let `doctor` write to a store that already exists: adds its observation, but breaks the rule that `doctor` is read-only.

## Verdict

Implemented. A1, A3 and A4 hold from the first candidate. A2 holds after the fix commit, with `doctor` and `selftest` as the documented exceptions. No live installation was attempted (§9).

## Recommendation

Keep `doctor` and `selftest` out of telemetry, as the [runtime contract](../runtime-contract.md#telemetry-observations) now states. Merge-result CI remains the publication gate.
