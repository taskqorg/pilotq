# CoreQ observations in PilotQ (#374)

## Question

Implement [task #374](https://github.com/taskqorg/pilotq/issues/374): write PilotQ operations through
the shared CoreQ observation contract, obtain agent records from agentq-runtime, and retain the
old PilotQ path until a later parity task. The implementation follows R13, R16, R17 and §§8–9.

## Findings

- **A1:** `pilotq.md` §8 states the observation contract before implementation. The operation
  catalogue, installation path, audit joins and compatibility boundary live in the linked
  [runtime detail](../runtime-contract.md#telemetry-observations). CoreQ is v0.21.0 and
  agentq-runtime is pinned to `c80675a557417532393e143ca2783c0f4c83b8d9`.
- **A2:** CLI commands, terminal requests, manager capabilities, installed TaskQ calls, Telegram
  delivery and service passes write metadata to the existing CoreQ `telemetry.sqlite` store.
  Request text and tool output remain in the journal. Audit exposes request/trace IDs and
  `telemetry_links`; the relationship is resolved at read time. Missing values and unclassified
  unsuccessful tool results stay unknown with reasons. No second collector or exporter is added.
  Idle passes and repeated host and board reads fold into CoreQ's 15-minute `method.aggregate` rows.
- **A3:** `Run::record` supplies `agent.turn` and `agent.call`. PilotQ neither parses model calls
  for telemetry nor synthesizes provider tokens, process usage or missing runtime identities.
  It checks the runtime's append result and attempts recording on terminal and interrupted paths
  after a launch handle is available. A runtime that cannot produce a report stays unavailable.
- **A4:** The journal, `pilotq.request` events and `pilot report` remain active. The old event and
  new terminal request observation append together. No store or report deletion is included;
  no same-window production parity is claimed. `pilot report` reads `failed` as unknown with a
  reason when pruned rows may lie inside its window.

### Idle passes displaced request records

The second review of `ace4219` measured an idle service with no TaskQ at 15.9 rows/s and replayed a request row out of the store after 101376 rows. The capacity prune removes the oldest rows, so `pilot report` then undercounted failures (A2, A4, R17, §8).

| Finding | Rule | Before | After |
|---|---|---|---|
| Idle passes wrote one row each | A2, A4 | 482 to 2400 rows in 121 s, 15.9 rows/s | 11 to 11 rows in 121 s, 0.00 rows/s, by the same style of run against an invented local Telegram API |
| Repeated board reads and the status hostname wrote rows outside the passes | A2, A4 | With TaskQ configured, each 30 s pass added `pilotq.host`, `taskq.read` and `service.steady` rows | No row other than aggregates, poll rows and store checkpoints added in 95 s |
| Cleanup of an exited process group read as failed | A2 | `pilotq.cleanup` `method` row with `failed` on each bounded command | The routine exit reads `ok` and folds; other `kill` failures stay failed |
| Pruned rows could hide a failed request | R17 | `failed` counted only retained rows | `failed` is null with `telemetry pruned rows inside the reported window` |

The fix uses CoreQ's existing repeating root rather than a new fold:

- An idle pass adds to its operation's aggregate, which keeps calls, failures and total duration. A pass that handled items, failed or stayed unfinished keeps its own `service.pass` row.
- `service.boards` and `service.typing` report a polled level, not work, so only a changed level keeps a row with its count.
- `service.drafts` now counts drafts sent, not previews seen. `service.board` drops its constant count of 1.
- `capture::poll` was not used. It measures its own closure, which cannot span the async passes, and it adds a change row per transition that the capacity prune removes last.

New guards, each run with its fix removed and seen failing:

- `idle_passes_374_fold_and_exceptions_keep_rows` protects the fold, its counts and the rows that must stay.
- `idle_service_374_keeps_request_rows_and_adds_no_row_per_pass` runs a real service with TaskQ configured across the 30 s board observer. It asserts behaviour only, with no size or time threshold.
- `pilot_report_374_reads_unknown_when_rows_were_pruned_in_its_window` protects the unknown report.

Retained limits:

- Each folded operation still writes one aggregate per 15-minute window, and working passes and agent records still consume capacity. CoreQ can therefore still prune old records, and the report then reads unknown instead of a low count.
- Abrupt termination can lose the current window's counts. Orderly exits flush them.
- No soak longer than these runs was attempted, and no live installation (§9).

Both new tests of the previous round were run with their fix removed, and both failed. The link test also proves that a trace was current, because its healthy pass must write one link before the broken pass runs. The `/restart` change has no dedicated test: only an installed service reaches that path.

Linux candidate gate on `b194939`, from an LF checkout in WSL:

- `scripts/check-contract.sh`: passes at 300 lines, with the existing headroom warnings.
- `cargo test --locked --no-fail-fast`: lib 1 passed; binary 248 passed, 5 ignored; `telegram` 78 passed, 10 ignored; `update` 12 passed. This includes `u23_audit_through_service_and_cli`, which the earlier macOS sandbox blocked.
- `cargo run --locked -- selftest`: passes.

Windows portable check: `cargo test --locked --lib` passes 1 test. This does not qualify a managed Windows host. A Windows checkout with `core.autocrlf=true` cannot run the binary tests, because `src/instructions.rs` expects LF in its included documents. Linux runs therefore use an LF checkout.

Merge-result CI, live installation and same-window parity are not covered by these checks (R19).

## Options

- Keep `doctor` and `selftest` out of telemetry: preserves their §9 no-write boundary, but leaves those two commands without an observation.
- Let `doctor` write to a store that already exists: adds its observation, but breaks the rule that `doctor` is read-only.

## Verdict

Implemented. A1, A3 and A4 hold from the first candidate. A2 holds after the fix commit, with `doctor` and `selftest` as the documented exceptions. No live installation was attempted (§9).

## Recommendation

Keep `doctor` and `selftest` out of telemetry, as the [runtime contract](../runtime-contract.md#telemetry-observations) now states. Merge-result CI remains the publication gate.
