# Automatic image access on non-image outcomes (#316)

Report: fix for [task #316](https://github.com/taskqorg/pilotq/issues/316), implementing A1–A4 under pilotq.md §5, R13 and R16. Version 0.2.39 is a candidate; no installation or release is performed.

## Question

Can automatic notifications avoid image-access errors for non-image outcomes while retaining fail-closed retrieval and truthful ambiguity handling for real images?

## Findings

### Failure evidence

The PM retained private live 0.2.38 evidence: outbox entries 2049–2051 sent image gaps for non-image outcomes while two existing issue-read keys were eligible. The worker uses that supplied live observation; it does not copy private Telegram content or inspect live secret values. No live credentials, grants, services, capacity or models were changed.

The local regression `result_images_316_nonimage_and_ambiguous_keys` failed before the implementation at “automatic non-image result must skip key selection”. It uses a current trusted closed outcome, registered board-only project and two eligible invented fixture keys. Initial compilation required initializing the repository's pinned specq submodule; that setup failure was not product evidence.

### Change and retained protection

The latest trusted outcome is checked for supported direct image references before selecting image credentials. Attachment-free and ZIP-only automatic observations stay silent; explicit requests retain an unavailable/unsupported gap. Multiple eligible keys fail closed with a truthful English or Russian explanation; explicit authorized selection still works. Image gaps use fixed public categories instead of interpolated tool diagnostics. The root contract and Telegram specification own this distinction.

Regression protection covers empty and ZIP-only outcomes, unchanged key last-use metadata, ambiguous real-image selection, English/Russian gap projection and explicit authorized selection. Existing filtered image tests cover inline photo transport, per-photo receipts, exact task revision, route/access/repeat/actor fences, board identity, JPEG/PNG signatures, authenticated transfer, size bounds, metadata and redirect/archive refusal. Fixture key stores are temporary invented data, never live key changes.

Independent read-only review found no blocking task-fit or implementation defects.
